### กลุ่ม A — รูปลักษณ์ทั่วไป (spec ข้อ 4-6, 9, 13-15)

- [ ] **ข้อ 4 — เทียบกับการ์ดบนหน้า:** เปิดโมดัลทั้ง 6 ตัว (AddPallet, EditPallet, ยืนยันลบ/ตัดออก,
      BulkTransaction, PalletDetail, QRPrint) แล้ววางเทียบกับการ์ดสถิติบนหน้าคลังพาเลท —
      มุมมนต้องเท่ากัน (`rounded-3xl` ทั้งคู่), โทนสีพื้นต้องเป็นอุณหภูมิเดียวกัน,
      ปุ่มต้องทรงเดียวกับปุ่มอื่นในแอป และ**ต้องไม่เห็นสี `blue-600`/`indigo-600`/`purple-*`
      เหลืออยู่เลยด้วยตา**
- [ ] **ข้อ 5 — แอนิเมชันเปิด:** โมดัลต้อง "เด้ง" เข้ามาเห็นได้ชัด (`animate-pop-in`)
      ไม่ใช่โผล่มาทันทีแบบไม่มีทรานซิชัน
- [ ] **ข้อ 6 — ล็อกสกรอลล์:** เปิดโมดัลใด ๆ แล้วลองเลื่อนหน้าพื้นหลัง — ต้องเลื่อนไม่ได้
      และความกว้างหน้าต้องไม่กระตุก (ไม่มี layout shift จาก scrollbar หาย) ปิดโมดัลแล้ว
      ต้องเลื่อนพื้นหลังได้เหมือนเดิม
- [ ] **ข้อ 9 — โมดัลอยู่เหนือแถบเลือกลอย:** ติ๊กเลือกพาเลทบางแถวให้แถบเลือกลอยขึ้นมา
      แล้วเปิดโมดัลจากแถบนั้น (เช่น BulkTransaction) — โมดัลต้องอยู่เหนือแถบ ไม่ถูกแถบบังส่วนใด
- [ ] **ข้อ 13 — เส้นแบรนด์วิ่งขณะบันทึก:** กดปุ่มยืนยัน/บันทึกที่มีการเรียก API
      (เช่น สร้างพาเลท, บันทึกแก้ไข) แล้วดูขอบบนของโมดัลขณะรอผลลัพธ์ — ต้องมีเส้นสี accent
      วิ่งอยู่ (ตัวเดียวกับ progress indicator ที่ใช้ตอน login)
- [ ] **ข้อ 14 — `PalletDetail` เลื่อนเฉพาะเนื้อใน:** เปิดพาเลทที่มีประวัติหลายสิบรายการ —
      หัวโมดัล (รหัสพาเลท+badge) และท้ายโมดัล (ปุ่มปิด) ต้องอยู่นิ่งกับที่
      มีแค่เนื้อตรงกลาง (ไทม์ไลน์) ที่เลื่อนได้
- [ ] **ข้อ 15 — Ctrl+P ใน QRPrint ไม่เพี้ยน:** เปิด QRPrint แล้วกด Ctrl+P (หรือปุ่มพิมพ์)
      ต้องได้แผ่น QR ออกมาเหมือนเดิมทุกประการ (ตรรกะสร้างเอกสารพิมพ์ไม่ถูกแตะ)

### กลุ่ม B — พฤติกรรม Escape / โฟกัส / คลิกพื้นหลัง (spec ข้อ 7, 8, 10, 16)

- [ ] **ข้อ 7 — Escape ปิดทีละชั้น:** เปิด `PalletDetail` → คลิกรูปหลักฐานเพื่อเปิด
      `ImageViewer` ซ้อนขึ้นมา → กด Escape ครั้งเดียว → **ต้องปิดแค่รูป**
      `PalletDetail` ต้องยังเปิดอยู่ → กด Escape อีกครั้งจึงปิด `PalletDetail`
      (และสกรอลล์พื้นหลังต้องคลายล็อกก็ต่อเมื่อปิดชั้นสุดท้ายแล้วเท่านั้น)
- [ ] **ข้อ 8 — Escape ไม่ล้างการเลือกแถว:** ติ๊กเลือกพาเลทหลายแถว → เปิด `BulkTransaction`
      → กด Escape → โมดัลต้องปิด **แต่การเลือกแถวต้องไม่หาย** (แถบเลือกลอยต้องยังโชว์จำนวนเดิม)
- [ ] **ข้อ 10 — คลิกพื้นหลัง เลือกปิดตามชนิดโมดัล:** คลิกพื้นที่มืดรอบกล่องของ
      `AddPallet` / `EditPallet` / `BulkTransaction` → **ต้องไม่ปิด** (มีข้อมูลกรอกอยู่ เสี่ยงหาย)
      แต่คลิกพื้นหลังของ `PalletDetail` / `QRPrint` / `ImageViewer` → **ต้องปิด**
      (โมดัลอ่านอย่างเดียว ไม่มีอะไรจะเสีย)
- [ ] **ข้อ 16 — โมดัลยืนยันหน้าตั้งค่า/หน้ารายการ:** ไปหน้า Settings และหน้า Transactions
      ลองเปิดโมดัลยืนยัน (เช่น ลบผู้ใช้/ลบสถานที่ ถ้ามี) — ต้องได้หน้าตาใหม่ (สไตล์เดียวกับ
      ConfirmDialog ของหน้าคลัง) ทำงานเหมือนเดิมทุกอย่าง และตอนนี้ปุ่มยืนยันต้องขึ้นสถานะ
      "กำลังทำงาน" ระหว่างรอผลด้วย (ของเดิมไม่มี)

### กลุ่ม C — บั๊กที่ตั้งใจแก้ต้องยืนยันว่าหาย (spec ข้อ 11, 12)

- [ ] **ข้อ 11 — แก้รหัสพาเลทซ้ำ ต้องไม่ปิดโมดัลและไม่หายข้อมูล:** เปิด `EditPallet`
      ของพาเลทหนึ่ง แก้รหัสให้ตรงกับพาเลทอื่นที่มีอยู่แล้ว กดบันทึก —
      **โมดัลต้องไม่ปิด** ข้อความ error ต้องขึ้น**ใต้ช่องรหัส** (ไม่ใช่แค่ toast ลอย)
      และสิ่งที่พิมพ์ไว้ในช่องอื่น (เช่น หมายเหตุ) ต้องยังอยู่ครบ ไม่หาย
- [ ] **ข้อ 12 — ล้างวันที่ใน BulkTransaction แล้วกดยืนยัน:** เปิด BulkTransaction
      ลบค่าช่องวันที่ให้ว่าง แล้วกดยืนยัน — ต้องขึ้นข้อความ error **ใต้ช่องวันที่**
      ไม่ใช่เงียบหายไปเฉย ๆ (ของเดิมพัง เพราะ RangeError ถูกกลืนไปเงียบ ๆ)

### กลุ่ม D — คีย์บอร์ดล้วน ห้ามแตะเมาส์ (spec ข้อ 17-20)

ทำรอบนี้ทั้งรอบโดย**ไม่แตะเมาส์เลย** ใช้ Tab/Shift+Tab/Enter/ลูกศร/Escape เท่านั้น

- [ ] **ข้อ 17 — โฟกัสเข้า-ออกโมดัลถูกต้อง:** เปิดโมดัลด้วยคีย์บอร์ด (Enter บนปุ่มที่เปิดมัน)
      → โฟกัสต้องกระโดดเข้าไปในกล่องทันที → กด Tab ไล่วนดู — โฟกัสต้อง**วนอยู่ในกล่องเท่านั้น**
      ห้ามหลุดไปโดนอะไรข้างหลังโมดัล → กด Escape ปิด → โฟกัสต้อง**กลับไปที่ปุ่มเดิมที่เปิดมัน**
      (ทำซ้ำกับโมดัลอย่างน้อย 3 ตัวที่ต่างชนิดกัน เช่น ฟอร์ม/ยืนยัน/อ่านอย่างเดียว)
- [ ] **ข้อ 18 — ทุกช่องมี label ที่คลิก/แท็บได้จริง:** ไล่ Tab ผ่านทุกช่องในฟอร์มของ
      `AddPallet`, `EditPallet`, `BulkTransaction` — แต่ละช่องต้องมี label ที่มองเห็นได้
      (ทดสอบโดยคลิกที่ตัวหนังสือ label เอง แล้วดูว่าโฟกัสกระโดดเข้าช่องที่ถูกต้องหรือไม่)
- [ ] **ข้อ 19 — SegmentedControl เดินด้วยลูกศร:** ใน BulkTransaction แท็บไปที่สวิตช์
      "เบิกออก/รับคืน" แล้วกดลูกศรซ้าย/ขวา — ต้องสลับตัวเลือกได้ และ screen reader
      (หรือ accessibility inspector ของ browser devtools) ต้องประกาศว่ามันเป็น `radiogroup`
      ไม่ใช่ปุ่มสองปุ่มแยกกัน
- [ ] **ข้อ 20 — ช่อง error ประกาศถูกต้อง:** ทำให้ช่องใดช่องหนึ่ง error (เช่น รหัสซ้ำ หรือ
      วันที่ว่าง) แล้วตรวจด้วย accessibility inspector ว่าช่องนั้นมี `aria-invalid="true"`
      และข้อความ error ถูกผูกผ่าน `aria-describedby` (ถ้ามี screen reader เปิดอยู่
      ต้องได้ยินข้อความ error ถูกอ่านเมื่อโฟกัสเข้าช่อง)

### กลุ่ม E — สองภาษา EN/TH (spec ข้อ 21-22)

สลับภาษาแล้วเปิดโมดัลทั้ง 7 ตัวซ้ำ (AddPallet, EditPallet, ยืนยัน, BulkTransaction,
PalletDetail, QRPrint, ImageViewer) ในทั้งสองภาษา

- [ ] **ข้อ 21 — ป้ายไม่ตัดขาด ไม่ดันกล่องแตก:** โดยเฉพาะ**ปุ่มท้ายกล่อง**
      (ป้ายภาษาไทยมักยาวกว่า EN) และ**`SegmentedControl` ใน BulkTransaction**
      ("เบิกออก"/"รับคืน" เทียบ "Check out"/"Check in") — ต้องไม่มีคำไหนถูกตัด ไม่ล้น
      ไม่ทำให้กล่องเสียทรง ทั้งสองภาษา
- [ ] **ข้อ 22 — หัวเรื่องภาษาไทยไม่มีวรรณยุกต์เลอะ:** ดูหัวเรื่องของทุกโมดัลในภาษาไทย
      โดยเฉพาะจุดที่เคยเป็น `font-black` (รหัสพาเลทใน BulkTransaction, QRPrint) —
      ต้องไม่มีวรรณยุกต์ซ้อนทับตัวอักษรข้างล่าง (อาการนี้เกิดเพราะ font-weight 900
      ที่เบราว์เซอร์สังเคราะห์เอง ตอนนี้เปลี่ยนเป็น font-bold/font-semibold แล้วควรหายไป)

## จุดที่รู้อยู่แล้วว่าเหลือ (ตัดสินแล้วว่าไม่บล็อก)

รีวิวรอบสุดท้ายตัดสินว่าสี่ข้อนี้เป็น Minor ปล่อยไว้ได้ ไม่กระทบพฤติกรรมโค้ด:

3. `TextInput.tsx:10` — คอมเมนต์อ้าง `SelectField.tsx:48-52` ซึ่งเลขบรรทัดเลื่อนไปแล้ว
4. `t.inventory.working` กลายเป็นคีย์กำพร้าหลังรวมป้ายปุ่มไปใช้ `t.common.working`
