# ภาคผนวก ก ติดตั้งและเตรียมระบบ

ภาคผนวกนี้สำหรับผู้ที่ต้องนำระบบขึ้นใช้งานตั้งแต่ศูนย์ ผู้ใช้งานทั่วไปไม่จำเป็นต้องอ่าน
ทำตามลำดับ ก.1 ถึง ก.6 ครั้งเดียวจบ

## ก.1 สิ่งที่ต้องเตรียม

| รายการ | รายละเอียด |
|---|---|
| **Node.js** | เวอร์ชัน 18 ขึ้นไป |
| **npm** | ติดมากับ Node.js |
| **บัญชี Supabase** | สมัครฟรีที่ [supabase.com](https://supabase.com) ใช้เป็นฐานข้อมูล ระบบยืนยันตัวตน และที่เก็บรูปหลักฐาน |
| **บัญชี LINE Developers** | จำเป็นเฉพาะเมื่อต้องการให้ระบบส่งรายงานเข้า LINE ข้ามได้ถ้ายังไม่ใช้ |

## ก.2 ติดตั้งโปรเจคและตั้งค่า .env.local

**ขั้นที่ 1 ดาวน์โหลดโปรเจคและติดตั้งไลบรารี**

```bash
git clone https://github.com/bcozfair/nmt-pallet-system.git
cd nmt-pallet-system
npm install
```

**ขั้นที่ 2 สร้างโปรเจค Supabase**

1. เข้า [supabase.com](https://supabase.com) แล้วสร้าง Project ใหม่
2. ไปที่ **Settings → API**
3. คัดลอกค่าสองตัว: **Project URL** และ **anon public key**

**ขั้นที่ 3 สร้างไฟล์ `.env.local`**

สร้างไฟล์ชื่อ `.env.local` ที่โฟลเดอร์หลักของโปรเจค แล้วใส่ค่าที่คัดลอกมา

```env
VITE_SUPABASE_URL=https://xxxxxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
VITE_ADMIN_EMAIL_BASE=your-email@gmail.com
```

- `VITE_ADMIN_EMAIL_BASE` เป็นเพียง **ค่าสำรอง** ค่าจริงที่ระบบใช้อยู่ในฐานข้อมูล
  และแก้ได้จากหน้าตั้งค่า (หัวข้อ 4.6)

> **คำเตือน** ห้ามนำไฟล์ `.env.local` ขึ้น GitHub เด็ดขาด ไฟล์นี้ถูกกันไว้ใน
> `.gitignore` แล้ว ตรวจสอบก่อน commit ทุกครั้ง

## ก.3 เตรียมฐานข้อมูล Supabase

โครงสร้างฐานข้อมูลทั้งหมดอยู่ในไฟล์เดียวคือ
`supabase/migrations/00_current_schema.sql` ไฟล์นี้สร้างตาราง ฟังก์ชัน ทริกเกอร์
กฎความปลอดภัยระดับแถว (RLS) ที่เก็บไฟล์รูป และการซิงก์ข้อมูลแบบเรียลไทม์ ให้ครบในครั้งเดียว

1. เปิดโปรเจคใน Supabase แล้วไปที่เมนู **SQL Editor**
2. เปิดไฟล์ `supabase/migrations/00_current_schema.sql` คัดลอกทั้งไฟล์
3. วางลงใน SQL Editor แล้วกด **Run**
4. รันไฟล์ที่เหลือในโฟลเดอร์ `supabase/migrations/` ตามลำดับชื่อไฟล์ (`20260720_01`,
   `20260720_02`, `20260720_03`, `20260729_01`, `20260729_02`)

> **หมายเหตุ** ไฟล์ `20260720_*` และ `20260729_*` คือรูปแบบ ALTER ของการเปลี่ยนแปลง
> ชุดเดียวกัน มีไว้สำหรับฐานข้อมูลที่มีข้อมูลอยู่แล้วและสร้างใหม่ไม่ได้ ทุกไฟล์เขียนให้รันซ้ำได้
> การรันไฟล์แรกแล้วตามด้วยไฟล์ที่เหลือจึงไม่ทำให้เกิดข้อผิดพลาด

**ค่าเริ่มต้นที่ถูกใส่ให้อัตโนมัติ**

| ค่า | ค่าเริ่มต้น |
|---|---|
| เกณฑ์เกินกำหนด | 7 วัน |
| วันส่งรายงาน | ทุกวัน |
| เวลาส่งแจ้งเตือน (รอบเช้า) | 08:00 น. |
| เวลาส่งสรุป (รอบเย็น) | 16:00 น. |
| Channel Access Token / Your user ID | ว่าง — กรอกจากหน้าตั้งค่าภายหลัง |

**ปิดการสมัครสมาชิกเอง**

ระบบไม่มีหน้าสมัครสมาชิกสำหรับบุคคลทั่วไป บัญชีทุกบัญชีต้องถูกสร้างโดยผู้ดูแลระบบ
เพื่อไม่ให้ใครสร้างบัญชีเองด้วย anon key ให้ไปปิดที่
**Authentication → Providers → Email** แล้วปิดตัวเลือกที่อนุญาตให้สมัครสมาชิกเอง

## ก.4 สร้างผู้ดูแลระบบคนแรก

นี่คือขั้นตอนที่คนติดตั้งมักติด ระบบสร้างบัญชีใหม่เป็น **พนักงาน** เสมอ และการเปลี่ยน
บทบาทต้องทำโดยผู้ดูแลระบบที่มีอยู่แล้ว ฐานข้อมูลที่เพิ่งสร้างจึงยังไม่มีทางมีผู้ดูแลระบบ
คนแรกผ่านหน้าจอได้เลย ต้องสร้างจากฝั่ง Supabase โดยตรงหนึ่งครั้ง

**ขั้นที่ 1 สร้างบัญชีใน Supabase**

1. ไปที่ **Authentication → Users** แล้วกด **Add user**
2. ช่อง Email ให้ใส่อีเมลในรูปแบบ `ชื่อผู้ใช้+รหัสพนักงาน@โดเมน` โดยอิงจาก
   อีเมลหลักที่ตั้งไว้ เช่น อีเมลหลักคือ `your-email@gmail.com` และรหัสพนักงานคือ
   `ADMIN01` ต้องใส่ว่า `your-email+ADMIN01@gmail.com`
3. ตั้งรหัสผ่าน
4. ใส่ **User Metadata** เป็น JSON ดังนี้

```json
{
  "employee_id": "ADMIN01",
  "full_name": "ชื่อ นามสกุล",
  "department": "Warehouse"
}
```

**ขั้นที่ 2 ยกระดับเป็นผู้ดูแลระบบ**

ไปที่ **SQL Editor** แล้วรันคำสั่งนี้ โดยเปลี่ยน `ADMIN01` เป็นรหัสพนักงานที่ใช้จริง

```sql
update public.users set role = 'admin' where employee_id = 'ADMIN01';
```

**ขั้นที่ 3 ทดสอบ**

เข้าสู่ระบบด้วยรหัสพนักงาน `ADMIN01` และรหัสผ่านที่ตั้งไว้ ต้องเข้าสู่หน้าภาพรวมของ
ผู้ดูแลระบบ ไม่ใช่หน้าจอมือถือของพนักงาน

หลังจากนี้บัญชีอื่นทั้งหมดสร้างจากหน้าผู้ใช้งานได้ตามหัวข้อ 4.4 ไม่ต้องกลับมาทำขั้นนี้อีก

> **หมายเหตุ** ระบบกันไม่ให้ลบผู้ดูแลระบบคนสุดท้ายออกจากระบบ จึงไม่มีทางเผลอ
> ทำให้ฐานข้อมูลไม่เหลือผู้ดูแลระบบเลย

## ก.5 ตั้งค่า LINE Messaging API

ข้ามหัวข้อนี้ได้ถ้ายังไม่ต้องการให้ระบบส่งรายงานเข้า LINE ส่วนอื่นทั้งหมดใช้งานได้ตามปกติ

**ขั้นที่ 1 หาค่าจาก LINE Developers Console**

1. เข้า [developers.line.biz](https://developers.line.biz) แล้วสร้าง Provider และ
   Channel แบบ **Messaging API**
2. ที่แท็บ **Messaging API** คัดลอก **Channel access token** (ถ้ายังไม่มี ให้กดออกใหม่)
3. ที่แท็บ **Basic settings** คัดลอก **Your user ID**
4. เพิ่มบัญชี LINE Official Account ของ Channel นี้เป็นเพื่อนในแอป LINE ของผู้รับรายงาน

**ขั้นที่ 2 กรอกลงในระบบ**

1. เข้าสู่ระบบด้วยบัญชีผู้ดูแลระบบ ไปที่เมนู **ตั้งค่า**
2. วางค่าลงในช่อง **Channel Access Token** และ **Your user ID**
3. กด **"บันทึกการเปลี่ยนแปลง"** ป้ายสถานะต้องเปลี่ยนเป็น **"ตั้งค่าแล้ว"**
4. กดเมนู **"ทดสอบ"** แล้วเลือก **"ส่งแจ้งเตือน"** เพื่อตรวจว่าข้อความเข้า LINE จริง

**ขั้นที่ 3 เปิดรายงานอัตโนมัติ (ทำเมื่อต้องการให้ส่งเองตามเวลา)**

การส่งทดสอบในขั้นที่ 2 ใช้งานได้ทันทีโดยไม่ต้องทำขั้นนี้ แต่การส่งอัตโนมัติตามเวลา
ต้องมีสองอย่างเพิ่ม

1. ติดตั้ง Edge Function ชื่อ `scheduled-report` ในโฟลเดอร์
   `supabase/functions/scheduled-report/` ขึ้นโปรเจค Supabase
2. ตั้งค่าลับชื่อ `REPORT_TRIGGER_SECRET` ให้ฟังก์ชันนั้น แล้วตั้งงานตามเวลา (cron)
   ให้เรียกฟังก์ชันพร้อมส่งค่าลับนี้ในส่วนหัวของคำขอ

> **หมายเหตุ** ค่าลับนี้เป็นสิ่งที่พิสูจน์ว่าผู้เรียกคืองานตามเวลาจริง ไม่ใช่คนนอกที่เดาที่อยู่
> ของฟังก์ชันได้ ถ้าไม่ตั้งค่านี้ รายงานอัตโนมัติจะไม่ทำงาน แต่ปุ่มทดสอบส่งในหน้าตั้งค่า
> ยังใช้ได้ตามปกติ เพราะพิสูจน์ตัวตนด้วยบัญชีผู้ดูแลระบบที่กำลังเข้าสู่ระบบอยู่

## ก.6 รันระบบ และข้อควรรู้เรื่องกล้องกับ HTTPS

**รันสำหรับพัฒนา**

```bash
npm run dev
```

เปิดเบราว์เซอร์ที่ **`https://localhost:3000`**

> **หมายเหตุ** เป็น `https` ไม่ใช่ `http` และเป็นพอร์ต **3000** โปรเจคนี้เปิด HTTPS
> ไว้ที่เครื่องพัฒนาโดยตั้งใจ เพราะกล้องของมือถือใช้งานไม่ได้เลยถ้าไม่ใช่การเชื่อมต่อ
> ที่ปลอดภัย ใบรับรองที่ใช้เป็นแบบสร้างเอง เบราว์เซอร์จะเตือนว่าไม่ปลอดภัยในครั้งแรก
> ให้กดยืนยันเข้าใช้งานต่อได้

**ทดสอบบนมือถือจริง**

เซิร์ฟเวอร์เปิดรับทุกเครื่องในวงแลนอยู่แล้ว

1. ดูเลข IP ของเครื่องที่รันเซิร์ฟเวอร์ เช่น `192.168.1.20`
2. บนมือถือที่ต่อ Wi-Fi วงเดียวกัน เปิด `https://192.168.1.20:3000`
3. กดยอมรับคำเตือนเรื่องใบรับรอง
4. เข้าสู่ระบบด้วยบัญชีพนักงาน แล้วกด "เบิกออก" เพื่อทดสอบว่ากล้องเปิดได้

> **ข้อควรระวัง** ถ้าเปิดด้วย `http://` ธรรมดา กล้องจะไม่ทำงาน และหน้าจอจะขึ้นว่า
> **"ไม่สามารถเข้าถึงกล้องได้ หรือเปิดเครื่องสแกนไม่สำเร็จ"** ซึ่งดูเหมือนระบบพัง
> ทั้งที่สาเหตุคือโปรโตคอล ตรวจว่าที่อยู่ขึ้นต้นด้วย `https://` เสมอ

**สร้างไฟล์สำหรับใช้งานจริง**

```bash
npm run build
```

ไฟล์ผลลัพธ์จะอยู่ในโฟลเดอร์ `dist/` นำไปวางบนโฮสต์ที่รองรับ HTTPS ได้

**คำสั่งอื่นที่มีให้**

| คำสั่ง | ใช้ทำอะไร |
|---|---|
| `npm run preview` | เปิดดูผลลัพธ์จาก `npm run build` |
| `npm run typecheck` | ตรวจชนิดข้อมูลทั้งโปรเจค รวมถึงคำแปลที่ตกหล่น |
| `npm run test` | รันชุดทดสอบทั้งหมด |
